# 동도금 PM 모니터링

실제 웹 진입 파일은 `index.html`입니다. 기존 `pm_schedule.html` 요구사항과 이후 Work/Codex 수정 기록을 통합합니다. 기존 영구 저장 키를 그대로 사용합니다.

## 사용 흐름

- **오늘 브리핑**: 오늘/내일 일정과 공정별 카드 확인 → 공지 복사. 카톡 공지 반영 바로가기를 제공합니다.
- **진척 게이지**: 화학동 진행, 일반 전기동 더미, 펄스 4단계 타이머 확인.
- **화학동 관리**: 화7·8·9·13·14 시작/완료 및 시간정정. 수동 분 입력은 00/30분이며 기존 저장값·메시지의 분 정밀도는 유지합니다.
- **특이사항 수동**: 오늘/내일 규칙 PM 및 일반 화학동, 디스미어 13/14 입력. 라인별 태그를 제공합니다.
- 주간 매트릭스와 액퍼내기는 헤더의 별도 창으로 엽니다.
- 연결·데이터 관리에서 현재 기기의 데이터와 서버 저장 대기열을 JSON으로 백업할 수 있습니다. 인증 정보와 붙여넣은 대화 원문은 포함하지 않습니다.

## 적용 순서와 유지하는 후속 변경

Gemini 정리 이후의 수정은 아래와 같이 우선 반영합니다.

- 전12도 산탈지.산세.박리를 기본 PM으로 사용합니다. 전9·14·20·21도 같은 기본 명칭입니다.
- 진행 중 공지 문구는 `-화13 10시 PM 진행중` 형태입니다. 작업명·분은 데이터와 현황 카드에 보존합니다.
- 전기동은 항상 7시패스로 고정합니다. 붙여넣은 공지와 이전 저장값의 다른 패스 시각은 적용하지 않습니다. 브리핑·복사 원문·게이지가 같은 기준을 사용합니다.
- 디스미어 13/14는 수동 기준일 이후 실제 화학동 완료 2회마다 1회 안내합니다. 기준일을 등록하지 않으면 자동으로 과거 회차를 추정하지 않습니다.
- 디스미어 공지는 화학동 상태를 바꾸지 않습니다. 수동 등록으로 기준일을 관리합니다.
- 첫 화면은 브리핑·공지 복사에 집중합니다. 화학동 상세 관리는 화학동 탭으로 모으며, 브리핑의 상태 요약을 누르면 해당 필터로 바로 이동합니다. 공지 반영은 입력창으로 바로 열리는 별도 창에서 처리합니다.
- 앱을 열기 위해 Google 로그인을 요구하지 않습니다. 기존 Firebase 권한으로 서버 동기화를 원하는 경우에만 선택적으로 연결합니다.
- 미병합 PR #8의 백라이트/완료 인식과 #13의 대시보드·수집 메시지 연동을 최신 main의 공지·패스 수정과 통합했습니다.

## 공정 기준

- 에칭: 일요일을 포함한 에1.2 → 에3.4 → 에6 3일 순환. 2026-09-25는 에3.4 기준입니다.
- 화학동: 실제 완료 후 72시간. 화8 완료 후 48시간 초과 시 빌드업 금지.
- 화학동 진행: 12시간 액이송, 14시간 미완료 지연. 다음 PM까지 7시간 이내면 임박 표시.
- 일반 전기동: 08:30 기준 12시간 후인 20:30부터 미완료 지연. 더미 1.5시간.
- 펄스: 0.5 DC → 1.5 DC → 펄스패스 → 펄스더미, 단계별 1.5시간.
- 일일 브리핑의 화학동 포함 범위는 당일 08:30 이상부터 익일 08:30 미만입니다.
- 격주 기준과 전체 매트릭스는 기존 일정을 유지합니다.

## 공지와 저장 처리

- 날짜 없는 진행/완료 공지의 시간이 현재보다 미래면 전날로 해석합니다. 날짜가 명시된 미래 기록은 완료로 반영하지 않습니다.
- 오래된 시작·완료 공지는 최신 기록과 작업명을 덮어쓰지 않습니다. 정정은 시간정정을 사용합니다.
- 백라이트 보고에서 PM인 라인만 진행 근거로 보관합니다. 이후 날짜·시각이 있는 양산/액수위 신호가 나오면 완료 후 72시간을 계산합니다. 일반 측정값, 미완료·취소·예정 표현은 완료로 만들지 않습니다.
- 완료 메시지 날짜·시각이 없으면 확인 입력을 요구하고 공지 원문을 유지합니다.
- 버전이 다른 저장 키는 동적으로 검색하되 마스터를 우선합니다. 손상된 항목은 유효한 이전 버전에서 복구합니다.
- 실제 기록이 없는 화학동 라인은 기본 날짜로 임의의 진행/지연을 표시하지 않습니다. 5개 라인은 항상 보이며 ‘기록 확인 필요’로 표시합니다.
- 변경 대기열과 Firebase transaction을 사용합니다. 서버 접근/저장이 실패하면 기기 데이터를 보관합니다.
- 수집 메시지 완료도 수동 완료와 같은 회차 식별자로 집계해 디스미어 계산의 중복을 막습니다.

## 서버 연결

현재 프로젝트는 기존 Firebase 데이터베이스를 사용합니다. 서버의 비로그인 접근이 거부되면 기기에 저장됩니다. 다른 기기의 데이터가 자동으로 합쳐졌다고 표시하지 않습니다.

이 변경은 Firebase 보안 규칙, GitHub Secret Protection, Google Apps Script 트리거, Mac 예약 수집 설정을 변경하지 않습니다. 기존의 메일 중지 상태를 되돌리지 않습니다. 수집기 실행 방법과 제약은 [automation/README.md](automation/README.md)를 참고하세요. 수집기 코드 제공만으로 무인 수집이 작동한다는 뜻은 아닙니다.

## 검증

Node.js 18 이상에서 외부 서비스 없이 실행합니다.

```sh
node --test tests/pm-regression.cjs tests/kakao-automation.cjs
```

실행 검사는 분리한 DOM/Firebase 모의 환경을 사용합니다. 화면 검증은 운영 Firebase SDK를 제거한 로컬 사본에서 수행합니다. 실제 iPhone Safari 확대·키보드 동작과 무인 카톡 수집은 별도 실기기 검증 대상입니다.
